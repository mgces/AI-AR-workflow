# DSH 云端 Agent 编排平台复核报告

日期：2026-09-16（追加复核）
复核范围：官方 DSH Web 单入口、AR Delivery P0–P8 编排、Claude/OpenCode/Codex 适配、SSH Workspace Gateway、RAG、设备与产物调试、审核与维测投影、云端生产化边界。

## 结论

当前版本已经达到“可信本地/私有内网 MVP”可用：官方 DSH Web 是唯一入口，AR 面板嵌在同一页面；运行状态、阶段门禁、人工审核、人工输入、失败原因、CodeAgent 进程、token usage、产物和设备调试均有 API 与页面投影。P0–P8 的确定性流程在 fixture adapter 下可以完整走通；本地 Connector + SSHFS 和 remote-tools MCP 路径也已经具备云端下发、真实本地 CLI 执行、取消、重连和远端 gate 编排的单工作区闭环。真实宿主、真实 CLI 账号、设备与发布权限仍需现场验收。

它还没有达到“公网多租户生产云”或“真实三环境 AR 业务验收”完成。当前仓库没有真实 OpenHarmony 产品根，也没有真实 HarmonyOS-system/HarmonyOS-chip profile；因此 P4–P8 的编译、真机、发布和 Gerrit 结果不能用本地 fixture 证明。免登录入口只应部署在可信内网、SSH 隧道或已有身份代理之后。

## 本轮已修正

- 人工审核等待改为按 `wait_id` 配对，并在阶段和运行两层计算区间并集；新增 `wall_elapsed_ms`、`human_wait_ms`、`effective_elapsed_ms`、`human_wait_intervals`。存在旧事件无法闭合时，整体等待和有效耗时保持 `null`，不会把未知当作零。
- `task.awaiting_consent` 与 `human.action_recorded` 使用确定性 `wait_id`；重放事件不会重复计算人工等待。
- 调度器失败记录绑定 `attempt_id`，同一失败重试或断线回放通过持久 operation journal 去重。
- 官方 DSH AR 页面、阶段表、人工等待表和 JSON/CSV 导出均展示墙钟、人工等待、有效执行时长及数据质量。
- P8 的 HarmonyOS/Gerrit 路径改为外部 profile 驱动，真实 push、Change-Id、revision、绿色评审标签和查询时间会绑定到证据；缺少 profile 或查询程序会在不可逆动作前硬失败。
- 本地和远端 CodeAgent 执行都会在 finally 清理临时提示词；ProcessSupervisor 只持久化参数摘要，不再把提示词写入 `args_json`。
- P0 现在先检查同一工作区中的完整 gate bundle（11 个 gate、`lib/environments.py` 和 delivery bridge）；远端通过 `workspace.probe` 逐文件核验可达性、类型和源码入口可执行位。
- 远端多项目工作区的 `repo_root`、AR 默认路径、gate bundle 和 bridge 按本次 run 的项目根解析；省略部署路径时由适配器注入标准路径，避免预检通过后实际 profile 找不到脚本。
- 无效或缺失的远端根目录返回可读的 `repo_root_invalid`/`remote_root_invalid` 阻塞结果，不会在路径拼接处抛出未处理异常。
- 新增单工作区 WSS Connector：云端 `/v1/connect` upgrade、hello/心跳、请求相关、超时/取消、连接 epoch 和断线清理；本地 Connector 固定执行 `probe`、`agent.start`、`agent.status`、`agent.cancel`。
- Connector hub 新增文件持久 outbox：幂等命令的 pending/completed/failed 状态以 0600 权限原子写入，云端进程重启后可以按 `operation_id` 重绑 pending 操作或直接回放已完成/失败结果，并对同一 operation 的输入指纹冲突硬失败。
- Connector 在启动命令进入时即登记可取消操作，挂载预检期间收到取消也会被安全回收；本地根目录会做真实路径和读写权限检查，并拒绝软链接逃逸。
- CodeAgent 刷新会主动请求 Connector 重新探测，因此页面反映用户电脑上后来安装或移除的 CLI；custom 命令通过受限 argv 配置参与同一探测和派发路径。
- 新增本地 Connector remote-tools MCP：不安装 SSHFS 时，本地 Claude Code/OpenCode/Codex 通过一次性 Unix socket 访问 SSH 工作区；各 CLI 使用原生配置入口，Codex 临时 home 保留本机文件认证，超时/取消会回传到 SSH operation。
- 新增 `platform/deploy/doctor.mjs`、systemd 单元和环境模板；doctor 会分别判断 P0/P8 是否可启动，缺少 gate、profile、CodeAgent、hdc 或发布工具时返回结构化阻断，而不是让服务启动后才暴露隐性错误。
- ProcessSupervisor 已接入可选 Linux cgroup v2：best-effort 回退会留下原因，required 在子进程启动前失败；Gateway、local-console 和官方 DSH plugin 均可从环境变量加载该策略。
- 修正云端部署资产：systemd 的官方 DSH Web 单元现在显式加载 `/opt/dsh/AI-AR-workflow/platform/deploy/cordis.cloud.patch.yml`；新增 Nginx TLS/WebSocket 模板，doctor 可探测官方 DSH 可执行文件、patch 文件并拒绝仍指向开发机 checkout 的 patch。
- systemd Web 单元已改为直接使用固定的 `/opt/dsh/official/.../dsh` 和 canonical patch 路径；不再依赖 systemd 对 `EnvironmentFile` 变量的 `ExecStart` 展开，避免服务启动时把 `${DSH_DSH_COMMAND}` 当成字面量。
- Web 单元在 ExecStart 前还会重新检查 DSH 可执行文件和 patch 可读性；部署资产在 doctor 之后被删除或替换时会直接阻止启动。
- Gateway 支持以 root-owned 绝对路径 JSON 文件加载固定 CodeAgent/AR gate profiles，systemd 环境模板已默认指向 `workspace-gateway/examples/ar-delivery-profiles.json`；缺文件、相对路径、非对象 JSON 或与内嵌变量冲突会在启动前失败。
- 云端 DSH 到 Gateway 的 HTTP envelope 已支持在运行时解析 `${DSH_GATEWAY_BEARER_TOKEN}` 这类受控环境变量引用；canonical cloud patch 与两侧环境模板使用同一 Bearer secret，缺失 secret 会保持未解析并由 Gateway 返回 401，不会绕过授权或把 secret 写回 patch。
- 部署 doctor 现在可以读取两个 systemd EnvironmentFile，验证 DSH Web 与 Gateway 的 Bearer secret 都已配置且一致，并验证 DSH `DSH_AUTHORITY_SHARED_SECRET` 与 Gateway `DSH_GATEWAY_SHARED_SECRET` 的配置、32 字节最小长度和一致性；它拒绝 `${TOKEN}`、空值和含空白的未解析占位，报告只返回配置状态和原因，不回显 secret。
- canonical cloud patch 现在显式绑定 `tenant_id=tenant-1`、`workspace_id=workspace-1`，并把 DSH 的 `workspaceId` 与 Gateway/Connector 工作区统一；远程 CodeAgent、SSH gate、RAG、设备和产物请求不会因缺少 Authority envelope 身份字段在插件初始化时失败。
- 本地 CodeAgent 命令解析已覆盖 Windows 原生 npm `.cmd/.bat` 包装器，通过 PowerShell JSON argv 桥传递 prompt 和参数；不会把 prompt 拼接为 shell 命令，`DSH_POWERSHELL_COMMAND` 可指定 `pwsh.exe` 或 `powershell.exe`。
- 使用官方 DSH Web 配置启动了一次真实 Connector loopback smoke：官方页面完成 `/v1/connect` WebSocket upgrade、hello/工作区登记，页面收到 Claude Code/Codex 的在线状态和缺失 CLI 的明确原因；另有 6/6 真实 HTTP upgrade → 本地 CodeAgent 修改工作区、usage 和产物引用回传测试。
- 使用临时回环 OpenSSH 代码端完成真实 remote-tools smoke：本地 Connector 通过 SSH 读写源文件、调用登记的 profile 并把日志/产物引用回写 SSH pipeline；同时修复了远端新文件写入时 `target_real` 未初始化的问题，Gateway 全量测试增至 83/83。

## 前置条件和代码端路径

启动 P0 前，页面会同时核验代码根、Python/Git、完整 gate bundle、环境分支和可派发的 CodeAgent。选择
OpenHarmony 时要求可执行 `build.sh`、`developer_test` 目录和可执行 `start.sh`；HarmonyOS 必须先选择
`system` 或 `chip` 并绑定对应 profile、产品、设备和发布后端。P0 可启动不代表 P8 就绪，设备、真实编译
工具链和 GitCode/Gerrit 回执仍由后续 gate 决定。

CodeAgent 有四种当前可用路径：官方 DSH Claude provider、本机 `opencode`/`codex` 非交互 CLI、用户电脑
Connector 中探测到的 Claude/OpenCode/Codex/custom CLI，或登记在 Workspace Gateway 的远端 profile。
Connector 路径会让本地 CLI 在 SSHFS 挂载的代码目录中修改文件，云端仍通过 Gateway 运行 Python gate、编译、
设备和发布 profile；Gateway profile 路径则让 CodeAgent、Python gate 和产物都在同一 SSH 代码主机运行。
两条路径都不把云端收到的字符串当作任意 shell。无挂载源码的 remote-tools/MCP 适配已实现，当前仍需
针对真实 CLI 固定版本完成长时任务、账号、断线和工具行为验收。

本地 CLI 不能把 `ssh://` 当作 `cwd`。使用 SSHFS 时要在本机提供受控挂载，再把挂载后的绝对路径交给
Connector；大仓扫描、编译、权限、软链接和断线恢复的成本会明显增加。无挂载时可使用已实现的
remote-tools MCP：CLI 在本地临时 sandbox 中运行，源码读写和固定 profile 通过一次性 broker 到 SSH
代码主机；或改用 Gateway 远端 profile，让 Agent 直接在 SSH 代码主机运行。

## 必须关闭的缺口

### P0：上线前必须关闭

1. **传输与身份**（T08）：WSS upgrade、hello/心跳、请求相关、超时、取消、重连、连接 epoch、mTLS/Origin 策略、设备配对/撤销、ACK、断线回放和文件持久 outbox 已有单工作区实现；公网生产仍需实际证书终止、外部密钥轮换、真实连接审计，HTTP/JSONL 只能保留为受控内网调试通道。
2. **租户与数据边界**（T09/T25）：接入 OIDC/SSO 或等价身份层、tenant/workspace RLS、CSRF 与 Origin 校验、短期授权、对象存储、密钥托管、备份/恢复/保留策略和配额。免登录不能直接暴露公网。
3. **远端执行安全**（T04）：部署目录已有 systemd/cgroup 模板、资源/磁盘/CPU/输出上限和 required 模式；仍需在云主机授予 cgroup 子树，补宿主故障后的进程存活证明、锁对账和重启恢复验收。
4. **真实工程分支**（T21）：提供并签名绑定 OpenHarmony、HarmonyOS-system、HarmonyOS-chip 的 product、out_dir、root markers、编译/测试 runner、设备类型和发布后端；未知或占位必须硬阻塞。
5. **真实 AR 业务验收**（T19/T20/T24）：在三类真实代码仓分别跑 P0–P8，完成 P4 编译、P5 单测、P6 设备、P7 质量和 P8 GitCode/Gerrit 发布，保存 commit/patchset、设备 serial、产物 hash 和 gate 回执。

### P1：进入稳定运营前关闭

1. **云端 RAG**（T22）：部署 Qwen embedding/reranker、pgvector 或等价向量库、增量分块、租户 ACL 撤销、模型版本/索引版本、评测集、限流和保留策略。
2. **CodeAgent 长任务回归**（T00）：用真实 Claude Code 和 OpenCode 账号跑长任务、取消、断线、恢复、额度耗尽和部分产物回放；Cursor/Trae 只有探测结果，尚无适配器。
3. **审核与隐私**：新执行路径的 `ProcessSupervisor` 只保存参数摘要，本地和远端临时提示词都会在 finally 清理；仍需对旧数据库记录和备份执行一次保留/迁移审计，并为异常终止设置宿主侧清理任务。
4. **旧运行对账**：没有新 `wait_id` 或 action 事件的历史 run 会标记为 `partial/unknown`，不能直接与新 run 做效率比较；需要一次迁移/对账任务和页面提示。
5. **部署交付物**（T25）：systemd、环境模板、doctor 和健康检查已纳入版本化部署目录；反向代理、密钥注入、日志轮转、监控告警、迁移和容量压测仍需在干净云主机复现。

## 发布建议

现在可以把它作为 WSL 或私有计算云的单节点内网服务继续使用和联调；可使用官方 DSH 页面中的 AR Delivery、CodeAgent 设置、RAG、调试、审核和维测导出。对外发布前必须先关闭 P0 项，并用真实三环境和两种 CodeAgent 补齐业务验收。当前定向回归通过只表示实现切片和契约稳定，不能替代这些外部依赖。单工作区的本地 Connector + SSHFS 或 remote-tools MCP 路径已经可以支撑完整 P0–P8 编排；真实 CLI、生产身份和真实设备仍按验收缺口处理。
