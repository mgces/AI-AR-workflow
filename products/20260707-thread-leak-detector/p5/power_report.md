# thread_leak_detector 功耗增量报告 (P5)

## 方法
rk3568 开发板无独立电量计,功耗以 CPU 占用为代理指标(插件无射频/GPS/屏幕等独立耗电源,
唯一功耗来源即 CPU)。数据同性能报告:真机、真实默认阈值(2000/3000)、常态运行 65.1s。

## 实测数据
- hiview 常态 CPU 占用: **0.138%** 单核(见性能报告)
- 轮询周期: 30s 一次,单次仅内存/procfs 读,无 wakeup-heavy 轮询、无持锁自旋。
- 定时器基于 ffrt 任务循环(`ffrt::submit_h` + `this_task::sleep_for`),复用 hiview 既有工作线程,
  不新增独立唤醒源/wakelock。
- 触发路径为一次性(one-shot 去重),不产生持续功耗。

## 结论
常态功耗增量与 0.138% CPU 等价,量级可忽略;无新增 wakelock、无高频唤醒,不影响待机功耗。
30s 轮询间隔相较更短周期显著降低唤醒频率。
